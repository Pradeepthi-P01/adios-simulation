\section*{Appendix: Derivation of the Capacity Bounds}
\label{sec:appendix}
Here we summarize the mathematical steps underpinning Equations~\eqref{eq:sbw}--\eqref{eq:breakeven} and confirm the arithmetic under baseline settings.

\textbf{Busy-Wait Worker Service Time.} A fraction $h$ of requests hit local memory, occupying a worker for $t_L$. The remaining $1-h$ fraction fault on remote memory, holding the worker through both CPU phases plus the unloaded network fetch ($t_c + t_f$, neglecting link queueing). Taking the expectation produces Equation~\eqref{eq:sbw}. Across long horizons, $N$ worker threads supply $N$ worker-microseconds of processing capacity per microsecond. With each completed transaction consuming an average of $S_{bw}$ core-microseconds, saturation throughput is bounded by $N/S_{bw}$. Using our default values: $S_{bw} = 0.2 \times 0.85 + 0.8 \times 5.3 = 0.17 + 4.24 = 4.41~\mu$s, yielding $\Lambda_{bw} = 8 / 4.41 = 1.814$~MRPS.

\textbf{Yielding Worker Service Time.} Local hits consume $t_L$ as before. On misses, workers execute $t_c$ total computation while offloading the network wait, paying one thread switch ($t_s$) upon fetch initiation and another ($t_s$) upon thread resumption. Total worker occupancy is therefore $h\,t_L + (1-h)(t_c + 2t_s)$. At default values, this evaluates to $0.17 + 0.8 \times 2.34 = 2.042~\mu$s, providing a CPU saturation limit of $\Lambda_{cpu} = 8 / 2.042 = 3.918$~MRPS.

\textbf{Network and Queue-Pair Bottlenecks.} Because only misses traverse the network, each fetch claims the physical link for $t_\ell = 0.5~\mu$s. The link can transfer at most $1/t_\ell = 2.0$ pages per microsecond, bounding aggregate throughput to $1 / ((1-h)\,t_\ell) = 1 / (0.8 \times 0.5) = 2.50$~MRPS. Furthermore, misses distribute across $N$ independent queue pairs with service time $t_q = 1.0~\mu$s, establishing a QP capacity ceiling of $N / ((1-h)\,t_q) = 8 / 0.8 = 10.0$~MRPS. Comparing the three bounds identifies the 100~GbE link as the limiting bottleneck at 2.50~MRPS.

\textbf{Break-Even Threshold Analysis.} Comparing CPU occupancies reveals that yielding requires less worker time than busy-waiting whenever $t_c + 2t_s < t_c + t_f$, simplifying to $t_s < t_f / 2$. As long as context switching is cheaper than half the remote fetch latency, yielding achieves higher core capacity. In our simulation, the empirical crossover occurs at $t_s \approx 1.57~\mu$s rather than exactly 1.50~$\mu$s because link queueing slightly suppresses the measured busy-wait plateau below theoretical capacity (1.77 vs.\ 1.814~MRPS). Solving $\Lambda_{cpu}(t_s) = 1.772$~MRPS yields $t_s = 1.565~\mu$s, matching our interpolated measurements.

\textbf{Low-Load Latency Calibration.} Under light traffic (0.5~MRPS), queueing delay is negligible. With $1-h = 0.80$, the median request is a miss. A remote access executes $t_c = 2.3~\mu$s of CPU computation and spends $t_f = 3.0~\mu$s on the wire, completing in exactly 5.30~$\mu$s under busy-waiting. Under pure yielding, the thread incurs an extra context switch ($t_s = 0.02~\mu$s), completing in 5.32~$\mu$s. This 20~ns measured gap provides direct empirical confirmation of our service-time implementation.
